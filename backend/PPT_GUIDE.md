### 슬라이드 1 — 표지

**제목**: FlatRoad — 전동이동보조기기 사용자를 위한 안전 경로 안내 서비스

**부제**: AI 기반 장애물 탐지 및 실시간 경로 공유 플랫폼

**발표자**: 이재행 (AI 모델 개발 · 백엔드 서버 구축 · 지도 데이터 연동 담당)

### 슬라이드 2 — 문제 정의

**제목**: 전동휠체어 사용자가 겪는 현실적인 문제

**내용**:
- 보행자 내비게이션은 계단·볼라드·경사로 등을 고려하지 않음
- 장애편의시설(엘리베이터, 장애인화장실, 경사로) 위치 정보가 흩어져 있음
- 볼라드(통행 방해 구조물)가 전동휠체어 동선을 예고 없이 막음
- **"갈 수 있는지 없는지를 미리 알 수 없다"** → 사고·불편 반복

**핵심 메시지**: 사용자가 직접 장애물을 촬영·공유하고, AI가 자동 분류해 모든 사용자의 경로에 반영하는 크라우드소싱 안전지도

### 슬라이드 5 — 데이터 수집 및 라벨링

**제목**: 볼라드 탐지 모델을 위한 데이터 구축

**내용**:

1. **공개 보행로 데이터 수집** (2026-03-03 ~ 03-07)
   - 공개 데이터셋 + 직접 촬영 이미지 병행 수집
   - 다양한 환경(주간/야간/우천/실내) 포함

2. **현장 이미지 촬영** (2026-03-08 ~ 03-14)
   - 직접 현장 방문하여 볼라드, 계단, 경사로 촬영
   - 다양한 각도·거리·조명 조건에서 수집

3. **라벨링(Annotation)** (2026-03-15 ~ 03-26, 12일 소요)
   - YOLO 포맷(`.txt`) 바운딩박스 라벨링
   - 클래스: `Bollard` (볼라드 단일 클래스 분류)

4. **데이터 정제 및 포맷 변환** (2026-03-27 ~ 04-02)
   - 중복·불량 이미지 제거
   - 학습/검증/테스트셋 분리 (8:1:1 비율)

**시각화 제안**: 라벨링된 볼라드 이미지 스크린샷 2~3장, 데이터셋 분포 파이차트

### 슬라이드 6 — AI 모델 선정 배경 (핵심 슬라이드)

**제목**: Detectron2에서 YOLOv5로 — 모델 전환 결정 과정

**배경**:
- 초기 계획: Facebook AI Research의 **Detectron2** (Mask R-CNN 기반) 사용
- 실험 과정에서 실서비스 적용에 한계 발견 → **YOLOv5**로 전환 결정

**전환 이유 (비교표)**:

| 항목 | Detectron2 | YOLOv5 | 결정 이유 |
|------|-----------|--------|----------|
| **추론 속도** | ~200ms/장 | **~15ms/장** | 실시간 분석 필수 |
| **서버 배포** | 복잡한 의존성, CUDA 필수 | **경량, CPU 지원** | 별도 GPU 서버 불필요 |
| **모델 크기** | 수백 MB | **YOLOv5s 14MB** | 로컬 서버 환경에 적합 |
| **파이썬 통합** | 설정 복잡 | **PyTorch 네이티브** | FastAPI 서버 스택 통일 |
| **실시간 API 연동** | 배치 처리 중심 | **단일 이미지 즉시 응답** | 앱 → 서버 업로드 즉시 분석 필요 |

**결론**: 전동이동보조기기 사용자가 장애물 촬영 후 **즉시** 경고를 받아야 하는 서비스 특성상, 추론 속도와 경량 배포가 핵심 요건 → YOLOv5 채택

**발표 멘트 예시**:
> "초기에는 인스턴스 분할에 강점이 있는 Detectron2를 검토했으나, 실제 구현 과정에서 추론 지연(200ms 이상)과 GPU 의존성이 모바일 앱과의 실시간 연동에 적합하지 않다고 판단했습니다. YOLOv5는 동일한 볼라드 탐지 성능을 유지하면서 추론 속도가 10배 이상 빠르고, CPU 환경에서도 안정적으로 동작하여 최종 채택하였습니다."

### 슬라이드 7 — YOLOv5 모델 학습 결과

**제목**: 볼라드 탐지 모델 — 학습 결과 및 성능

**내용**:

- **모델**: YOLOv5s (Small — 14MB, 빠른 추론 최적화)
- **탐지 대상**: Bollard (볼라드/통행방해구조물) 단일 클래스
- **학습 환경**: Python 3.10, PyTorch, yolov5 라이브러리

**서버 로드 확인 로그**:
```
[YOLO] 모델 로드 완료 — 클래스: ['Bollard']
INFO: Application startup complete.
```

**실제 탐지 결과 예시**:
```json
{
  "detected": true,
  "label": "Bollard",
  "confidence": 0.87,
  "message": "볼라드 감지됨 (신뢰도 87%)"
}
```

**시각화 제안**: 볼라드 탐지된 이미지에 바운딩박스 표시된 결과 스크린샷

### 슬라이드 8 — FastAPI 백엔드 서버 설계

**제목**: AI 추론을 담당하는 백엔드 서버

**내용**:

**API 구성**:
```
FastAPI 서버 (Python)
├── POST /api/obstacles     ← 장애물 등록 + AI 자동 분석
├── GET  /api/obstacles     ← 전체 장애물 조회 (지도 표시)
├── POST /api/obstacles/{id}/vote  ← 투표 (위험/해소됨)
├── POST /api/analyze        ← AI 단독 분석 (이미지만 전송)
└── GET  /                   ← 서버 상태 확인
```

**강조 포인트**:
- 장애물 등록 즉시 YOLOv5 자동 분석 → 결과 반환
- 비동기 처리로 동시 다수 요청 안정 처리
- 팀원 폰에서 WiFi로 직접 연결 테스트 가능

### 슬라이드 9 — AI 추론 파이프라인

**제목**: 사용자가 촬영하면 AI가 즉시 분석

**흐름 다이어그램**:
```
[사용자 — 볼라드 촬영]
        ↓
[Expo Go 앱 → POST /api/obstacles]
  - 이미지 (base64)
  - GPS 좌표 (latitude, longitude)
        ↓
[FastAPI 서버]
  - 이미지 디코딩
  - YOLOv5 추론 실행 (~15ms)
  - 탐지 결과: Bollard 87%
        ↓
[모든 사용자 지도에 볼라드 마커 표시]
        ↓
[경로 계산 시 50m 이내 볼라드 → ⚠️ 경고]
```

**핵심 메시지**: 촬영 → 서버 전송 → AI 분석 → 지도 반영이 자동으로 연결됨

### 슬라이드 10 — 지도 필터 기능

**제목**: 장애편의시설 실시간 지도 표시

**내용**:

현재 위치 기반으로 반경 3km 내 장애편의시설 즉시 검색

| 필터 버튼 | 아이콘 | 데이터 출처 | 검색 방식 |
|----------|--------|-----------|----------|
| 경사로 | ♿ (초록) | Kakao 로컬 검색 | `무장애`, `배리어프리`, `휠체어경사로` |
| 엘리베이터 | 🛗 (파랑) | Kakao 로컬 검색 | `엘리베이터` |
| 장애인화장실 | 🚻 (보라) | Kakao 로컬 검색 | `장애인화장실` |

**구현 특징**:
- 버튼 재탭 시 마커 일괄 제거 (토글)
- 페이지네이션으로 최대 45개 시설 표시 (3페이지 × 15개)
- 중복 좌표 자동 제거 (Set 기반 deduplication)

**시각화 제안**: 앱 실행 화면에서 엘리베이터 필터 활성화된 스크린샷

---

### 슬라이드 11 — 데모 시연

**제목**: 실제 동작 시연

**시연 순서**:
1. 앱 실행 → 현재 위치 지도 표시
2. 장애물 촬영(기여하기 탭) → 볼라드 촬영 → AI 분석 결과 팝업 확인
3. 홈 지도에 새 볼라드 마커 자동 추가 확인
4. 필터 버튼(엘리베이터) 탭 → 주변 엘리베이터 마커 표시
5. (시간 여유 시) 경로 탐색 → 볼라드 경고 표시

**백업 자료** (시연 실패 대비): AI 분석 결과 스크린샷, 필터 마커 스크린샷

### 슬라이드 12 — 결론 및 향후 계획

**제목**: 완성된 것과 남은 것

**완성된 기능**:
- ✅ YOLOv5 볼라드 탐지 AI 모델 (실시간 추론 ~15ms)
- ✅ FastAPI 백엔드 서버 (장애물 등록·조회·투표 API)
- ✅ 장애편의시설 지도 필터 (경사로·엘리베이터·장애인화장실)
- ✅ 크라우드소싱 장애물 데이터 자동 지도 반영

**향후 개선 계획**:
- 성능 튜닝: AI 신뢰도에 따른 마커 색상 차등 표시

- 모델 고도화: 볼라드 외 다양한 장애물 클래스 추가 학습
